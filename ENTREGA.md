# Roteiro para apresentar uma entrega técnica

Use este roteiro para uma página de revisão ou uma demonstração curta. Ajuste os campos ao projeto.

## Problema e público

Qual tarefa ficou mais clara ou mais fácil de reproduzir? Quem usará o resultado? Qual decisão a entrega pretende apoiar?

## Entrada e execução

Informe o arquivo de exemplo, a versão do projeto e o modo usado. Identifique se os dados são fictícios, fatos públicos selecionados ou material autorizado para uso local. Uma versão de modelo só deve ser informada quando puder ser verificada.

## Evidência observada

| Resultado | Evidência | Limite |
|---|---|---|
| O que aconteceu na execução | Saída, teste ou fonte que permite conferir | O que isso ainda não demonstra |

## Alternativas e decisão proposta

Compare as opções que a entrada permite avaliar. Para custos, preserve unidade, moeda, snapshot de preço e premissas de utilização. Para IA, diferencie validação de formato, referências e verificação semântica.

## Pendências

Liste informações que realmente mudariam a decisão. Identifique quem precisa revisar uma ação que altere estado, conceda acesso ou envolva orçamento, usando os papéis fornecidos no cenário.

## Próxima melhoria

Escolha uma melhoria pequena, um caso que a exercite e o resultado esperado. Uma correção reproduzível é mais útil que uma promessa ampla de qualidade.
